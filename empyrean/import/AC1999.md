# A world base from ac1999

`empyrean-import ac1999` converts the world of [ac1999](https://gitlab.com/adamplumb/ac1999), a
reconstruction of Asheron's Call as it launched in November 1999, from one exact commit into a
world Empyrean serves on its Launch era. It writes an ACE-schema SQL database, an Empyrean SQL
extension (the source's own loot generator and recipe costs), and a `world.pack` built from both,
with a ledger of every row it changed or left out and the committed source it read.

## Getting a world

Most operators fetch a world that has been built and checked, and don't build one:

```text
empyrean-import fetch --era launch --pack --out world.pack
```

That downloads the newest release of
[empyrean-world-launch](https://github.com/dereth-network/empyrean-world-launch), checks its SHA-256 and
writes its `world.pack`. The launcher does the same for a Launch world. A release there is a person's
decision: it says which ac1999 commit has been converted and played. The rest of this page is how
one is made, which anyone can repeat from any commit.

## What it needs

- **Dereth and Empyrean from this release or later**, both aware of the Launch era. Earlier ones
  cannot play this world: an earlier server refuses the pack, and an earlier client plays the
  wrong era over the wrong data files.
- **The 1999 data files**, which are not part of the world base and are never bundled: the
  `portal.dat` of October 31, 1999 and the retail CD's `cell.dat` of October 9, 1999 (the
  default `launch` target below). Point the server's `dat_files_directory` at the folder holding
  them. The client plays them beside a modern install's `client_*.dat` files, which draw its
  interface: `--dat-dir <modern folder> --classic-dat-dir <1999 folder>`. The launcher does this
  for you.
- **The server** configured for the era the pack was built for:

  ```toml
  [server]
  world_pack_path = "world.pack"
  dat_files_directory = "<the folder holding portal.dat and cell.dat>"
  [era]
  profile = "launch"
  ```

## Building it

Git must be installed. Supply the full 40-character commit SHA:

```text
empyrean-import ac1999 --revision <sha> --allow-incomplete --out <new-directory>
```

The command fetches that commit from `https://gitlab.com/adamplumb/ac1999.git`. To work offline,
add `--source` with a repository that already holds it, a converted bundle, or a candidate's source
ZIP. A repository is read as **committed Git objects**; a bundle or a source ZIP is checked file
for file against the SHA-256s it lists (the same files, no more and no fewer, at the same
revision) and refused if any differ. Dirty files, untracked files and the repository's current
checkout do not affect output; local replacement objects and archive attributes do not alter the
snapshot. Case-colliding or nonportable source paths refuse conversion.
Upstream programs, hooks and SQL servers are not run.

`--target` names the dats the world will be played with, and the manifest records each file's
capture date, header iteration and SHA-256:

| Target | `portal.dat` | `cell.dat` |
|---|---|---|
| `launch` (the default) | October 31, 1999, iteration 105 | the retail CD's, October 9, 1999, iteration 67 |
| `classic-1999-10-09` | the retail CD's, October 9, 1999, iteration 102 | the same |
| `source` | none: every row as the source wrote it, for the later files it was placed against | |

The October 31 portal holds every record of the CD's and 42 more, among them the fire elementals'
and the volcano's. Both 1999 targets play the CD's `cell.dat` unchanged, and both make the same
world from the source:

- **Yanshi.** The CD's cell numbering differs from the later files' in one building: the outpost
  generator, the vendor it links and the second vendor beside them (`0x7B973000`, `0x7B973001`,
  `0x7B973002`) move into the rooms of that building that contain their stored positions.
  Coordinates, rotations and timestamps are unchanged. Each moved row must match the reviewed
  source row field for field, or the conversion is refused; each is an `adapt` record in
  `changes.json` with its original cell.
- **Missing rooms.** Six placements name interior cells the CD lacks, and no room of their
  landblocks is the same room. They are dropped with their 18 linked children and links, and so is
  one portal destination (portal 3657 to `0x018A017F`).
- **Art the 1999 portal lacks.** The snowman, the scarecrows, the pumpkin and the jack o' lantern
  keep their definitions, but every placement, generator entry, create-list entry and emote that
  would make one appear is dropped, with the links and link generators left empty by it. An
  administrator can still create them.

That is all the conversion takes away for the world's own sake: what ac1999 has, its events and
what it dates to launch included, is ac1999's to decide, and is kept whatever the patch history says.

Each dropped row is a `quarantine` record in `changes.json` with its reason; the manifest names the
world policy. A reviewed row the source has changed refuses the conversion. One it has since removed
is listed in the manifest's `world_policy.reviewed_but_gone`, since that can only leave less to
drop.

The output directory must not exist; its parent must exist. Builds use an isolated sibling staging
directory and publish only after strict pack validation. A failed run leaves that staging directory
for inspection. Existing outputs are never overwritten. Build the command with
`cargo build --profile test-release -p empyrean-import` during development.

## Bundle contents

| File | Purpose |
|---|---|
| `world.sql` | Canonical ACE-schema tables and projected rows; load into an empty database selected by the operator |
| `empyrean.sql` | Supplementary recipe preconditions, grouped treasure and versioned loot inputs; apply after `world.sql` for Empyrean only |
| `empyrean-changes.json` | Rows restored by the Empyrean extension, separate from the canonical projection ledger |
| `world.pack` | Both SQL files imported for era `launch`, with source revision recorded as its base version |
| `manifest.json` | Exact revision, source-file hashes, pinned ACE schema, output hashes, counts and limitations |
| `changes.json` | Every normalized or quarantined table row, its original field values and reason |
| `pack-report.json` | Standard importer row/record counts, content identity and diagnostics |
| `source/` | Original committed database, treasure inputs and server license, including unsupported content |

The manifest has `status: incomplete` and `ready_for_gameplay: false`. `--allow-incomplete` accepts
the documented projection rules; it does **not** permit arbitrary unknown columns, unknown tables,
unread SQL or unrecognized death-loot schemas. An unfamiliar upstream change must be reviewed.
The supported source DDL is pinned to `5fe910e7a3e549d955117920a1bd30b4ee646938`;
changed definitions (including types, keys and removed columns) require an adapter update.
Comparison uses SQL tokens, ignoring comments and whitespace. Content files may not alter the
schema. The vendored source definition omits upstream line comments; committed inputs in a bundle
retain their original bytes. Projected SQL is also executed by the importer's SQL engine to check
target column ranges, widths and keys; a successful pack-only parse would not establish those.

The converter loads `1-Base/WorldBase.sql`, then all `3-Core` SQL files in deterministic path order.
The ACE schema is pinned to `ACEmulator/ACE` commit `47edade3bd3f6044b676d4eb877c4965c7eda62b`,
`Database/Base/WorldBase.sql`, included under ACE's AGPL-3.0 terms. The output omits database-wide
DROP/USE statements: the operator chooses a **new empty database**, rather than replacing a live one.
Schema compatibility with stock ACE is useful for inspection and further work; it does not provide
ac1999 gameplay rules or loot semantics to stock ACE.

Rebuild the pack independently:

```text
empyrean-import --sql <bundle>/world.sql --patches <bundle>/empyrean.sql --era launch --out <another-world.pack>
```

Identical source objects and converter/schema versions produce identical SQL, manifest and pack
bytes. Absolute acquisition/output paths and wall-clock timestamps are not artifact inputs.

## Current projection rules

- Quest cooldown `-1` becomes zero (no cooldown), retaining solve limits. Other negative values refuse
  conversion. This is a source-format normalization, not a claim that every quest rule is identical.
- Six-group death-loot rows are quarantined from canonical ACE SQL and restored in `empyrean.sql`
  as typed grouped profiles. All 39 reviewed tier/pool/mutation/spell/material files are compiled
  into a bounded, versioned policy record. They are not approximated with ACE's three loot groups.
- Recipes with extended modification blocks are quarantined as complete recipes, including cookbook,
  requirement and modification children. This preserves the preconditions instead of silently
  retaining a recipe whose cost/target semantics changed.
- The Empyrean extension restores reviewed success-player vital-only recipes. Current health,
  stamina and mana preconditions are checked before starting and again before completing a craft;
  the existing success modification applies its costs only on success. Mutation and stat-modification
  variants remain quarantined. Packs with these requirements carry a required capability bit, so
  older readers refuse them instead of silently omitting the checks. Ordinary ACE packs are unchanged.
- Missing direct weenie references in placed instances, encounters, create lists, non-treasure
  generators, emote actions and wielded loot are quarantined; links to removed placed instances are
  removed too. Missing spellbook entries are quarantined. Original rows remain in the ledger and
  source.
- Treasure and emote-spell references are settled before projection. The source's server reads a
  death treasure type from the wielded lists first, so the three practice dummies whose death type
  names a wielded list (`73`, `152`, `160`: bread, cheese and an apple) have that list written as
  their treasure create list. Six creatures name wielded types the source does not define (`71`,
  `78`, `220`, `250`, `300`) and two emotes cast spells it does not define (`2017`, `2648`); those
  rows are quarantined, as the source's own server would equip or cast nothing. Any other dangling
  death type, wielded type or emote spell refuses the conversion, and the written SQL is checked
  again before the pack is built.
- Other modeled content passes through the strict importer. No automatic EoR population is added.

Every model, picture, palette, sound and effect that a placed, generated, created, given, crafted,
looted or starting item can reach is present in the `launch` target's files. No retail data files
are bundled. A Launch profile is not proof that every early server rule is implemented or
historically verified.

## A release candidate

`empyrean-import ac1999 package --bundle <bundle> --out <new-directory>` turns a bundle into the
files a release would carry, and uploads nothing:

| File | What |
|---|---|
| `empyrean-world-launch-<commit>.zip` | The bundle's world: `world.pack`, both SQL files, the manifest and the ledgers |
| `empyrean-world-launch-<commit>-source.zip` | The committed source with `source.json`, its list of SHA-256s; `--source` rebuilds the world from it |
| `SHA256SUMS` | Both ZIPs and `release.json` |
| `release.json` | The source revision, the asset target and its files, the converter's commit, `Cargo.lock` and compiler, and the ZIP writer |

The same bundle always gives the same bytes: entries in path order, every one stamped
2000-01-01 00:00:00 with mode 0644, deflated at level 6 by the ZIP writer `Cargo.lock` pins, with no
directory entries or extra fields. The bundle's manifest records the converter's full commit, the
SHA-256 of the `Cargo.lock` it was built with and the compiler's version.

## Executable source loot

The `launch` era selects the `Ac1999` loot rules. Table 20 stores the six slot groups; table 21 stores the
compiled policy. Header capability `0x4` and overlay format `dereth world overlay v3 source loot`
make older readers reject these records. Existing ACE packs and earlier overlay formats retain
their behavior. A typed death-loot descriptor serves corpse, treasure generator/chest, inventory
and console rolls; Launch never falls back to ACE random loot when grouped data is missing.

Algorithm `ac1999-six-groups-v1` is ported from the AGPL-3.0 server at
`5fe910e7a3e549d955117920a1bd30b4ee646938`, `Server/Source/TreasureFactory.cpp` and
`Server/Source/PhatSDK/Support/RandomRange.cpp`. The policy records this algorithm revision
separately from the selected content revision and the SHA-256 of each of its 39 source files.
Changing content revisions does not imply that the corresponding server algorithm was reviewed.
Unknown fields, unsupported policy versions, malformed ranges, missing templates and missing SQL
spell records refuse conversion. Startup additionally checks referenced spell records against the
operator's installed DATs. Source loot has no runtime dependency on the source checkout.

Counts are inclusive and drawn before independent per-slot chances. Weighted weapon kinds,
base-tier fallback, entry weights, materials, palette selection, weapon/armor/value mutations,
spell-family limits, caster use spells, gem charges and activation requirements use this versioned
source algorithm. Tier support is 1 through 5, spell levels 1 through 6. The source's integer-divided armor
resistance increment is retained. Heritage values are translated by meaning into Empyrean's enum.
Generated thrown stacks also retain their generated unit value, so Empyrean's split, consume and
reload operations preserve the generated price. That unit-property update is an integration choice;
it is not present in the source generator's manual stack finalization.

This is source compatibility, not proof of November 1999 drop probabilities. The source includes
later reconstruction choices, including weapon weights derived from later evidence and recent
spell-count tuning. Distribution and property tests use original synthetic inputs, not retail
assets. Random seeds are not interchangeable with ac1999's multiple RNG streams. Spell schools
and base mana come from the installed DAT plus SQL; this implementation does not manufacture a
historical spell table. Full art/cell/quest closure and historical rule validation remain separate
operator checks. Preserve inherited authorship and applicable licenses when distributing inputs.
